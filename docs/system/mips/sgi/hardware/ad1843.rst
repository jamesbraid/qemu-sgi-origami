.. _sgi-ad1843:

===================
AD1843: audio codec
===================

Used in :ref:`sgi-ip32` (O2).
The AD1843 is a 16-bit stereo SoundComm codec from Analog Devices. The
O2 uses one, wired to the audio interface of the MACE I/O ASIC over a
serial TDM link. QEMU has no separate codec device. The codec is part of
``sgi-mace`` and lives in ``hw/mips/sgi/mace-audio.c``, beside the MACE
side of the interface (:doc:`mace`). The O2 test profile
(:doc:`../ip32`) carries it. The model follows the first silicon, revision
ID 1.

The codec is reached only through the MACE codec command register.
Software never addresses it directly.

Facts are rated as described in :ref:`sgi-ratings`.

.. _sgi-ad1843-identity:

Identity
========

Register 0 reads ``0xc001`` after reset: INIT and PDNO set, revision
identification 1. The data sheet gives the reset value and calls the
first version of the part "0001" :src:`ad1843-rev0 p. 28`, *established*.

The OpenBSD report of an O2 prints ``AD1843 rev 1`` for the audio device
at MACE offset ``0x300000`` (:src:`dmesgd-2432 mavb0`), *observed*. The
NetBSD report finds the same device at the same offset and prints
"can't power up conversion resources" instead of a revision
(:src:`dmesgd-5290 mavb0`), *observed*. The inventory says the AV1 and AV2
modules carry an AD1843 (:src:`bukosek-sgi-o2 Audio/Video I/O options`),
*observed*.

The same inventory prints the string "Iris Audio Processor: version A3
revision 0". What that string names, whether the codec, the MACE audio
interface or the audio subsystem as a whole, is *unknown*, and no source
ties the "A3" value to a codec register.

Reaching the codec
==================

Software writes a 24-bit word to the MACE codec command register. Bit 16
selects a read, bits 23:17 give the register address and bits 15:0 carry
the data to write. The word is sent on every TDM frame, and its reset
value has bit 16 set :src:`sgi-mace-2.0-spec p. 63`, *established*. The
last status word the codec returned reads back through a second register
:src:`sgi-mace-2.0-spec p. 63`, *established*. Linux builds the command word
the same way (``sgio2audio.c``), *software expectation*.

The MACE field is 7 bits wide and the AD1843 decodes 5. The model latches
the command once per frame, applies a write near the end of that frame and
returns a read's value a frame later, an *approximation*: the data sheet
and the MACE specification give no frame-level timing for register
access. An address of 32 or more is not passed on: the access logs
``LOG_UNIMP`` and returns nothing, an *approximation*.

Codec presence, the bit MACE reports in its control register, rises when
the serial clock first runs after INIT clears. The specification says only
"clock active" :src:`sgi-mace-2.0-spec p. 62`, so the delay is an
*approximation*.

Register map
============

The data sheet defines registers 0-28 and reserves 29-31
:src:`ad1843-rev0 p. 28-51`. Reset values are the data sheet's "initial
default state after reset" lines, checked against each register's page,
*established*. The model's writable mask is its reading of the field
tables: reserved bits read as zero and are not writable, *approximation*.
A write that sets a reserved bit logs ``LOG_GUEST_ERROR`` and stores the
other bits.

Reset, INIT and power-down
==========================

INIT is set after reset and clears "usually within 400 to 800 µs" once
reset is released, depending on the crystal circuit
:src:`ad1843-rev0 p. 28`, *established*. Register writes are blocked while
it is set. The model clears INIT 600 µs after the MACE codec reset is
released. A reset pulse shorter than 100 ns is ignored and logs
``LOG_GUEST_ERROR``, an *approximation*.

PDNO stays set until register 28 bit 15 (PDNI) is cleared and the part has
finished powering up. While PDNO is set the registers other than 16-24, 26
and 28 cannot be written, and the others return to their reset values
:src:`ad1843-rev0 p. 28`, *established*. The model does the same. It also
returns the mixer, gain and DAC registers to reset when their section is
disabled in register 27, a reading of the data sheet's "cleared to default
when" lines that is *inferred*.

The data sheet gives power-up as 470 ms and autocalibration as 4 ms, and
power-down as 5 ms :src:`ad1843-rev0 p. 10, 15, 49`, *established*.
Autocalibration always runs after a hardware reset and otherwise only when
ACEN (register 28 bit 14, set at reset) is set. The model uses these as
exact delays, 470 ms or 474 ms to leave power-down and 5 ms to enter it,
*approximation*: the data sheet gives them as typical or maximum values.
Changes to PDNI while a transition runs are ignored
:src:`ad1843-rev0 p. 49`.

Linux clears PDNI after reset and waits up to 500 ms for PDNO to clear
(``ad1843.c``, ``ad1843_init``), *software expectation*. That fits the
model's 474 ms worst case.

Clocks and serial frame
=======================

A 24.576 MHz crystal drives the part. As bus master it clocks the serial
bus at 12.288 MHz, or 16.384 MHz when SCF (register 26 bit 7) is set, and
a frame is 32 slots, or 16 when FRS (bit 6) is set
:src:`ad1843-rev0 p. 7, 10, 47`, *established*. The model follows both, with
the frame size taking effect at the point FRST selects. It supports the
three clock generators and the rate range of 4 kHz to 54 kHz
:src:`ad1843-rev0 p. 1`. A write that would enable a converter with an
unsupported rate, filter or mix combination is ignored and logs
``LOG_UNIMP``, an *approximation*: the data sheet does not describe
the part's response to such a write.

Sample formats
==============

Register 26 selects the DAC and ADC data format: 8-bit unsigned linear,
16-bit signed linear, 8-bit mu-law or 8-bit A-law. Each DAC can run in
mono, where slot 2 or 4 feeds both sides
:src:`ad1843-rev0 p. 47`, *established*. Eight-bit data is left-justified
in the 16-bit slot and the low byte is ignored
:src:`ad1843-rev0 p. 14, 22`, *established*. The model implements all four
formats, with piecewise G.711 companding for the two law formats. The
companding tables follow ITU-T G.711, not a captured codec output,
*approximation*.

Audio paths
===========

The model reproduces the digital and analog routing described in the data
sheet's block diagram: ADC sources, the DAC mixers, gains, attenuation and
the digital ADC-to-DAC mix. Only one output reaches the host. The DAC1 line
output plays as 48 kHz signed 16-bit stereo, and one host input voice feeds
the codec's AUX1 input. DAC2, the headphone and mono outputs and the other
inputs are modelled internally and are silent, *approximation*. See
:doc:`mace` for the ``audiodev`` property.

The two external control pins follow register 28 bits 9:8. The pins and
the power-down and mono-feedthrough inputs are exposed as GPIOs on
``sgi-mace`` for fixtures and the machine.

.. _sgi-ad1843-measurements:

Measurements
============

No register of this part has been read on a physical machine for this
project. Published captures are listed under Identity.

.. _sgi-ad1843-limits:

Model limits
============

- Only DAC1 line output and AUX1 input connect to the host. Everything
  else is silent, as above.
- The reset delay, power-up and power-down times and the 3.072 MHz phase
  grid are model choices.
- Which reserved bits are writable follows the model's reading of the field
  tables, not a measurement.
- The data sheet's rule that the mixer and gain registers cannot be
  written while their section is disabled is applied as a reset to default,
  not as a write block, *inferred*.
- Registers 29-31 read zero.
- Migration works only between identical builds.

Tests
=====

``tests/qtest/sgi-mace-audio-test.c`` has 33 cases on the MACE audio
interface and its codec. Those that pin the codec are ``codec-registers``
(reset values, masks and reserved bits), ``power-timing`` (INIT, power-up
and power-down), ``response-pipeline`` and ``serial-start-status`` (the
slot timing), ``rates-and-domains``, ``dma-formats`` and ``g711-encoding``
(sample formats), ``capture-nodes``, ``analog-routing``,
``dac-graph-gains``, ``digital-mix-constraints``, ``digital-attenuation``,
``dac-mix-branches``, ``phase-latches``, ``actual-phase`` and
``phase-crossings`` (clock generators), ``bit-conv-frequencies``,
``clock-continuity-reentry``, ``underrun-mix`` and
``migration-calibration``. The tests use the fixture device in
``tests/qtest/fixtures/sgi-mace-audio.c``, which pins the codec's external
pins and exposes its internal state.
