.. _sgi-aic7880:

=================================
Adaptec AIC-7880: SCSI controller
=================================

Used in :ref:`sgi-ip32` (O2).
The AIC-7880 is Adaptec's single-chip PCI SCSI host adapter with Ultra
(20 MHz) SCSI. The O2 has two on the MACE PCI bridge, at PCI devices 1 and
2, each with its own SCSI bus. They carry the internal disk and CD-ROM
(:doc:`mace`). QEMU models the part as ``aic7880`` in
``hw/scsi/aic7880.c``, and the ``o2`` machine (:doc:`../ip32`) fits two.

.. seealso::

   Platform pages: :ref:`sgi-ip32`.

Facts are rated as described in :ref:`sgi-ratings`.

No document about the AIC-7880 itself is public in the sources used here.
The register addresses, the reset values and the PCI layout come from the
data book of its predecessor, the AIC-7870, and from the Linux driver, which
supports both parts. A fact taken from the AIC-7870 is *inferred* for the
AIC-7880 unless this page says it was seen on an AIC-7880.

.. _sgi-aic7880-identity:

Identity
========

The PCI vendor ID is ``0x9004`` (Adaptec) and the device ID is ``0x8078``.
Linux lists ``0x8078`` as the AIC-7880 (``aic7xxx_pci.h``), *software
expectation*. The inventory shows two "Integral SCSI controller" entries
reading "Version ADAPTEC 7880" and PCI adapters with vendor ``0x9004`` and
device ``0x8078`` in slots 1 and 2 (:src:`bukosek-sgi-o2 My O2`), *observed*.
Both captures show the controllers at PCI device 1 and 2, with interrupts 8
and 9 on the CRIME input numbering
(:src:`dmesgd-2432 ahc0`, :src:`dmesgd-5290 ahc0`), *observed*.

The OpenBSD report prints revision ``0x00`` for both
(:src:`dmesgd-2432 ahc0`), *observed*. The model reads revision 0. It sets
no subsystem IDs, so they read zero, an *approximation*: no source reports
them. The class code is SCSI controller
(:src:`adaptec-aic-7870-data-book p. 114`), and the interrupt pin is INTA
(:src:`adaptec-aic-7870-data-book p. 62, 124`), as on the AIC-7870.

The NetBSD report shows "Ultra Wide Channel A, SCSI Id=0, 16/253 SCBs",
no SEEPROM and "left over BIOS settings" for each controller
(:src:`dmesgd-5290 ahc0`), *observed*. The OpenBSD report shows the same
chips negotiating 16-bit synchronous transfers at 20 MHz with an offset of
8 to one disk (:src:`dmesgd-2432 ahc0`), *observed*.

PCI configuration
=================

Base address 0 is a 256-byte I/O window, reset 1, with bits 31:8
writable. Base address 1 is a memory window, reset 0, whose address bits
move in 4096-byte steps with the 256-byte register file repeating inside
the 4 KiB range :src:`adaptec-aic-7870-data-book p. 119-120`, *established*
for the AIC-7870 and *inferred* for the AIC-7880. The model registers a
256-byte I/O BAR and a 4 KiB memory BAR, always, and the register file
repeats every 256 bytes inside the memory window.

On the AIC-7870, COMMAND bits 0, 1, 2, 4, 6 and 8 are writable and the
others read zero :src:`adaptec-aic-7870-data-book p. 109-110`. The model
uses QEMU's generic PCI mask plus parity error response: bits 0, 1, 2, 6, 8
and 10 are writable, so bit 4 is not and bit 10 is, *approximation*.
The MACE bridge further refuses COMMAND writes outside I/O enable,
memory enable, bus master and parity error response
(:ref:`sgi-mace-pci`).

Linux ORs ``0x1000`` into any four-byte read of configuration register ``0x40``
on the two onboard controllers, with the comment that the Ultra bit was never
set for the onboard SCSI chips (``ops-mace.c``), *software expectation*. The
model has no such fix-up. Register ``0x40`` reads zero on the ``o2``
machine, and ``0x600`` after reset when ``external-scb-ram`` is set.

Register map
============

The register file is 256 bytes, accessed one byte at a time. The model's
addresses match the Linux ``aic7xxx.reg`` file. The addresses in the
data book's tables 3-1 to 3-7 agree
:src:`adaptec-aic-7870-data-book p. 58-63`, *established* for the
AIC-7870. Linux uses the same addresses for the AIC-7880, *software
expectation*.

.. list-table::
   :header-rows: 1

   * - Offset
     - Registers
     - Notes
   * - ``0x00``-``0x1f``
     - SCSI block: SCSISEQ, SXFRCTL0/1, SCSISIGI/SCSISIGO (``0x03``),
       SCSIRATE, SCSIID, SCSIDATL, STCNT, SSTAT0/1, SIMODE0/1, SCSIBUSL,
       SHADDR, SBLKCTL
     - Reset zero, except SBLKCTL (below).
   * - ``0x20``-``0x5f``
     - Scratch RAM, 64 bytes
     - Used by the sequencer program.
   * - ``0x60``-``0x6f``
     - Sequencer: SEQCTL, SEQRAM, SEQADDR0/1, ACCUM, SINDEX, DINDEX,
       BRKADDR0/1, ALLONES, ALLZEROS, FLAGS, SINDIR, DINDIR, FUNCTION1,
       STACK
     - SEQCTL resets to ``0x90`` and BRKADDR1 to ``0x80``.
   * - ``0x84``-``0x9f``
     - Host block: DSCOMMAND0 (``0x84``), DSPCISTATUS (``0x86``), HCNTRL,
       HADDR (``0x88``), HCNT (``0x8c``), SCBPTR, INTSTAT, CLRINT/ERROR
       (``0x92``), DFCNTRL, DFSTATUS, DFDAT, SCBCNT, QINFIFO, QINCNT,
       QOUTFIFO, QOUTCNT
     - HCNTRL resets to ``0x05`` (paused, chip reset), DFSTATUS to
       ``0x21``.
   * - ``0xa0``-``0xbf``
     - SCB array page, 32 bytes
     - Sixteen pages, selected by SCBPTR.

The reset values for SEQCTL, BRKADDR1, HCNTRL and DFSTATUS are the data
book's initial values :src:`adaptec-aic-7870-data-book p. 60-61`,
*established* for the AIC-7870. The data book gives SBLKCTL a reset that
depends on the WIDEPS# strap. The model resets it to ``0xc2``, with wide
selection set, an *approximation*: the board's strap is unknown. Linux
calls the register at ``0x84`` DSCOMMAND0; the book calls it DSCOMMAND.

An access to a register the model does not implement logs ``LOG_UNIMP``.
A read returns ``0xff`` on the model. Either access pauses the sequencer, sets the error
state and raises the host interrupt, so a guest sees a stopped chip rather
than a silent success.

Sequencer
=========

The AIC-7870 sequencer runs from 512 words of 29-bit microcode RAM
(:src:`adaptec-aic-7870-data-book p. 4`), *established*, which the driver
loads through SEQCTL and SEQRAM. The model holds 512 instructions of four
bytes and runs the program the driver uploads, using the instruction format
and opcodes of the Linux assembler (``aicasm_insformat.h``), *software
expectation*. The call stack has four entries and is read through the STACK
register, two bytes per entry, low byte first
:src:`adaptec-aic-7870-data-book p. 105`, *established* for the AIC-7870.

The STACK register returns the entry pushed last first, low byte then
high byte, and its read pointer advances after each high-byte read, so eight
reads bring it back to where it started
:src:`adaptec-aic-7870-data-book p. 105`, *established* for the AIC-7870 and
*inferred* for the AIC-7880. The book lists an initial value of zero for the
register (:src:`adaptec-aic-7870-data-book p. 60`) but none for the individual
entries, which are *unknown*.
The model keeps the four entries as a circular buffer. A CALL moves the
pointer back one slot, modulo four, and stores the address of the following
instruction. A fifth CALL overwrites the oldest entry. A return loads the
newest entry and moves the pointer forward, modulo four. A return with
nothing pushed loads the stored word, which is zero at reset. None of these
cases sets the error state, an *approximation*: the book describes the STACK
reads, not overflow or underflow. The model zeroes all four words at reset, an
*approximation*. It reads STACK through the same pointer, advancing after each high byte.

ALLONES (``0x69``) reads ``0xff`` and ALLZEROS (``0x6a``) reads ``0x00``
:src:`adaptec-aic-7870-data-book p. 102`, *established* for the AIC-7870 and
*inferred* for the AIC-7880. NONE shares the ALLZEROS address, is write-only,
and a write to it as a destination changes nothing
:src:`adaptec-aic-7870-data-book p. 103`, *established* for the AIC-7870. The
model discards a host or sequencer write to ``0x6a`` and leaves ALLZEROS,
FLAGS and the other registers unchanged. A sequencer ADD of ALLONES and 1 into
NONE sets FLAGS (``0x6b``, ZERO bit 1, CARRY bit 0) to ``0x03``, and an ALU
return bit on that instruction still returns. The book names the two FLAGS
bits :src:`adaptec-aic-7870-data-book p. 103` but gives no per-instruction
update rule, so that flag result is an *approximation*. The book gives
ALLONES no write function. The model refuses a write to ALLONES from the host
or the sequencer and stops the sequencer, and ALLONES keeps reading ``0xff``,
an *approximation*.

FUNCTION1 (``0x6e``) turns bits 6:4 of the byte written to it into a single
set bit on read: a value of 0 reads ``0x01``, a value of 1 reads ``0x02``,
and so on up to ``0x80``
:src:`adaptec-aic-7870-data-book p. 104`, *established* for the AIC-7870 and
*inferred* for the AIC-7880. The book says nothing about bits 7 and 3:0 of the
written byte. The model ignores them when it decodes the read, so any byte with
the same bits 6:4 reads the same, an *approximation*. A sequencer ALU result
written to FUNCTION1 becomes the new input: after the model reads ``0x08``
from input ``0x30``, an ADD of ``0x10`` writes ``0x18`` and the next read
returns ``0x02``. The book lists no initial value for FUNCTION1
(:src:`adaptec-aic-7870-data-book p. 60`), *unknown*. The model resets the
input to zero, so FUNCTION1 reads ``0x01`` after a chip reset or a PCI reset,
an *approximation*.

Opcode ``0x9`` is JC, the branch taken when the incoming FLAGS CARRY bit is
set, and opcode ``0xa`` is JNC, the branch taken when it is clear. The Linux
assembler defines both and its sequencer program uses JC
(``aicasm_insformat.h``, ``aic7xxx.seq``), *software expectation*. The
AIC-7870 book defines neither. The model decides from the CARRY value present
before the instruction, not from a new comparison. On either outcome it reads
the encoded source, ORs in the literal immediate and writes the result to
SINDEX. It sets ZERO from that transferred byte and keeps CARRY, and it leaves
ACCUM and the source register unchanged. These transfer and flag effects are
an *approximation*: no source defines them.

The breakpoint compares the program counter with BRKADDR0 and bit 0 of
BRKADDR1, which holds address bit 8. Bit 7 of BRKADDR1, BRKDIS, disables the
comparison and resets to one
:src:`adaptec-aic-7870-data-book p. 101-102`, *established* for the AIC-7870.
A match sets INTSTAT BRKADRINT (bit 3) and pauses the sequencer, and
SEQCTL BRKADRINTEN (bit 3) decides whether it also drives the interrupt pin
:src:`adaptec-aic-7870-data-book p. 98, 141-142`, *established* for the
AIC-7870 and *inferred* for the AIC-7880. The model pauses with the program
counter at the break address and does not run the instruction there. It
raises the interrupt only while BRKADRINTEN is set, and setting BRKDIS lets
the instruction run. Pausing before the instruction runs is an *approximation*:
the book does not say which side of the instruction the pause falls on.

By default the sequencer runs without modelled time: it executes up to 256
instructions in a burst after each guest access or SCSI event. With the
``x-sequencer-clocked`` property it executes one instruction per cycle of
125 ns, or 100 ns when SEQCTL FASTMODE is set. The data book gives a
sequencer clock of 8 or 10 MHz, selected by FASTMODE, from a nominal 40 MHz
input clock (:src:`adaptec-aic-7870-data-book p. 4, 48, 53, 98`),
*established* for the
AIC-7870. The AIC-7880's clock and timing are *unknown*, so both modes are
an *approximation*. The ``o2`` machine does not set ``x-sequencer-clocked``.

.. _sgi-aic7880-host-path:

Host data path
==============

DFCNTRL (``0x93``) holds SCSIEN (bit 5), SDMAEN (bit 4), HDMAEN (bit 3),
DIRECTION (bit 2), FIFOFLUSH (bit 1) and FIFORESET (bit 0). Bit 6 is
WIDEODD, which has no effect except in a wide transfer with an odd byte
count, and bit 7 reads zero. A chip reset or PCI reset forces every bit to
zero. FIFORESET clears itself. FIFOFLUSH clears itself and has no effect while
the FIFO is empty
:src:`adaptec-aic-7870-data-book p. 145-146`, *established* for the
AIC-7870 and *inferred* for the AIC-7880. The model latches WIDEODD and reads
it back until a reset, with no effect on any transfer, because it has no wide
data path, an *approximation*. A write that sets bit 7 is refused and logs
``unsupported DFCNTRL control``. A write of ``0x43`` leaves ``0x40``, because
FIFORESET clears itself and the FIFO is empty.

DIRECTION set moves data from PCI memory to the data FIFO, and DIRECTION
clear moves it from the FIFO to memory
:src:`adaptec-aic-7870-data-book p. 146`, *established* for the AIC-7870.
HADDR (``0x88``-``0x8b``) counts up by one for each byte moved and HCNT
(``0x8c``-``0x8e``) counts down. A transfer with a zero count is inhibited.
Offset ``0x8f`` is reserved, always reads zero and ignores writes
:src:`adaptec-aic-7870-data-book p. 139-140`, *established* for the AIC-7870
and *inferred* for the AIC-7880. DFSTATUS HDONE is set when the count has
expired and the last transfer has finished, and FIFOFULL is set when every
byte location holds data
:src:`adaptec-aic-7870-data-book p. 148`, *established* for the AIC-7870.
The data FIFO holds 256 bytes
(:src:`adaptec-aic-7870-data-book p. 4`), *established* for the AIC-7870.
In the model, a host-only 256-byte transfer from memory (DFCNTRL ``0x05``,
then ``0x0c``) advances HADDR by 256, takes HCNT to zero and sets HDONE and
FIFOFULL, and the bytes then read back in order through DFDAT (``0x99``). That
transfer sets neither SDONE nor CMDCMPLT and queues nothing on QOUTFIFO. The
model returns zero from ``0x8f`` and ignores writes to it, also after a chip
reset and a PCI reset, and a write there leaves HADDR, HCNT and DFSTATUS
unchanged.

SHADDR (``0x14``-``0x17``) takes the same value as HADDR when HADDR is loaded.
Afterwards HADDR counts bytes moved on the host side and SHADDR counts bytes
moved on the SCSI side
:src:`adaptec-aic-7870-data-book p. 58-59, 171`, *established* for the
AIC-7870. In the model, a host-only transfer moves HADDR and leaves SHADDR at
the loaded value, and loading HADDR at ``0x88``-``0x8b`` shows the same bytes
at ``0x14``-``0x17``.

DSPCISTATUS (``0x86``) holds the FIFO threshold selector in bits 7:6, which
the host can write, and mirrors six PCI status bits in bits 5:0, which it
cannot. Bit 2 is received master abort
:src:`adaptec-aic-7870-data-book p. 136`, *established* for the AIC-7870 and
*inferred* for the AIC-7880. The model keeps the selector bits as written,
ignores writes to bits 5:0, and clears the selector on a chip reset or a PCI
reset without touching the PCI configuration registers. With the selector at
``0x80``, the model reads ``0x84`` after the QTest-only ``x-test-pci-error``
property sets received master abort. That property is a test hook, not a
hardware feature.

SCBPTR (``0x90``) selects a 32-byte page of the SCB array. The array has 16
internal pages, and a write of ``0xff`` reads back ``0xff`` whether or not
external SRAM is fitted
:src:`adaptec-aic-7870-data-book p. 63, 153`, *established* for the
AIC-7870 and *inferred* for the AIC-7880. The book does not say what an array
access with a pointer above 15 reaches. The model reads and writes page
``SCBPTR & 0x0f``, so page 16 is page 0 and page 255 is page 15, while SCBPTR
keeps all eight bits, an *approximation*. The model sets SCBPTR, QINCNT and
QOUTCNT to zero on a chip reset or PCI reset, matching the book's initial
values (:src:`adaptec-aic-7870-data-book p. 61, 63`), *established* for the
AIC-7870.

SCSI behaviour
==============

The model is an initiator. It runs one SCSI command at a time over a
QEMU SCSI bus with up to 16 targets and 8 logical units per target and no
tagged queueing. Selection addresses targets 0-15 when SBLKCTL selects the
wide connection, and 0-7 otherwise. Data moves by DMA through the data FIFO
and by byte-wise host access to DFDAT. Both read and write phases run as
asynchronous narrow transfers. A data phase with a nonzero synchronous
offset or wide transfer programmed in SCSIRATE sets the error state, an
*approximation* rather than a statement about the chip.

SCSIID (``0x05``) holds the target ID in bits 7:4 and the controller's own
ID in bits 3:0 :src:`adaptec-aic-7870-data-book p. 80`, *established* for the
AIC-7870 and *inferred* for the AIC-7880. SBLKCTL (``0x1f``) holds DIAGLEDEN
(bit 7) and DIAGLEDON (bit 6), both set at reset, AUTOFLUSHDIS (bit 5), clear
at reset, SELBUSB (bit 3), which always reads zero and ignores writes, and
SELWIDE (bit 1), loaded from the WIDEPS# strap at reset and writable after
that :src:`adaptec-aic-7870-data-book p. 96-97`, *established* for the
AIC-7870. The model stores all eight SCSIID bits as written, so target and own
IDs from 0 to 15 read back unchanged. It latches SBLKCTL bits 7:5 and 1 as
written and reads bit 3 as zero.

An ENSELO write in SCSISEQ starts a selection. SSTAT0 SELINGO (bit 4) is set
while the controller waits for the target to raise BSY and clears when the
target answers
:src:`adaptec-aic-7870-data-book p. 73, 84`, *established* for the AIC-7870.
With SXFRCTL1 ENSTIMER set, an unanswered selection ends when the timer
expires: the controller releases SEL and sets SSTAT1 SELTO (bit 7). With
ENSTIMER clear, SEL stays on the bus until the sequencer clears it
:src:`adaptec-aic-7870-data-book p. 76, 87`, *established* for the AIC-7870.
SSTAT1 BUSFREE (bit 3) is set once BSY and SEL have been negated for 400 ns
:src:`adaptec-aic-7870-data-book p. 87`, *established* for the AIC-7870. The
SXFRCTL1 STIMESEL field (bits 4:3) selects the timeout. The book's table prints
``256 s`` for value 0 and ``128 ms``, ``64 ms`` and ``32 ms`` for values 1 to 3
:src:`adaptec-aic-7870-data-book p. 76`: the unit conflicts with the other
three, so the first value is *unknown*. The Linux
driver documents 256, 128, 64 and 32 ms (``aic7xxx_osm.c``), *software
expectation*. The model uses 256, 128, 64 and 32 ms of virtual time, an
*approximation* that resolves the book's unit conflict in the driver's favour.
The model sets SELTO that long after the selection starts, releases SEL in the
same step, leaves SELINGO set, and sets BUSFREE 400 ns later. With SIMODE1
ENSELTIMO (bit 7) set, SELTO also latches INTSTAT SCSIINT, pauses the sequencer
and raises the interrupt. With ENSTIMER clear the model never sets SELTO. A
write that sets ENSTIMER during a pending selection starts the interval at
that write, and writing the same value again does not restart it, an
*approximation*: the book does not say how the timer starts.

The model refuses a selection whose target ID equals the controller's own ID,
for every ID from 0 to 15. It stops the sequencer and leaves SEL, SELINGO and
SELTO clear, an *approximation*: no source describes selecting oneself.

Interrupts raise INTA when the host interrupt enable is set, the chip is not
powered down and PCI bus master is enabled. INTSTAT carries the
sequencer, SCSI, break and error causes. The machine wires the two
controllers to MACE PCI interrupt inputs 0 and 1, which reach CRIME
slots 8 and 9 (:doc:`mace`).

.. _sgi-aic7880-limits:

Model limits
============

- The reset values, the BAR sizes and the sequencer clock come from the
  AIC-7870 and are provisional for the AIC-7880.
- One command at a time. Initiator mode only.
- Asynchronous, narrow data transfers only, though the real controllers
  negotiate wide and synchronous transfers (Identity).
- No tagged queueing, target mode, SEEPROM, option ROM, SCAM, or
  synchronous or wide negotiation.
- The ``external-scb-ram``, ``external-scb-size`` and
  ``external-scb-width`` properties model external SCB memory of 1, 2, 4
  or 8 KiB with 8 or 9 data bits. The ``o2`` machine does not set them.
- Configuration register ``0x40`` reads zero on the ``o2`` machine, and
  ``0x600`` after reset with ``external-scb-ram`` set. The model has no
  counterpart of the Ultra bit Linux ORs in on the O2.
- The ``o2`` machine accepts at most one SCSI disk or CD-ROM, at logical
  unit 0 and target 0 to 6, across both controllers, and refuses hotplug.
- ``o2-pci-diagnostic`` (QTest only) and ``o2-storage-diagnostic`` (reports
  every DMA to the machine) are test hooks, not hardware features.
- Revision and subsystem IDs are a model choice. An unsupported register
  access pauses the chip as described above.
- Migration works only between identical builds. A save while a command is
  in flight or a DMA is active is refused.

Tests
=====

``tests/qtest/aic7880-test.c`` is the controller's own test, with a
300 s timeout. Its case names show the areas: PCI
identity (``pci-identity``), command DMA, the function registers, SCB
pointers and aliases, external SCB RAM, wide selection, the PCI status
register, host DMA and FIFO thresholds, and the sibling policy
(``o2-sibling-policy-default``, ``o2-sibling-bar-repeats-last-slice``).
The sequencer additions are pinned by ``function-registers/constants``,
``function-registers/selectors``, ``function-registers/alu``,
``function-registers/none-return``, ``function-registers/refusals``,
``function-registers/state``,
``jc-branch-transfer``, ``jnc-branch-transfer``, ``circular-call-stack``,
``four-nested-calls``, ``or-return-without-call``, ``breakpoint`` and
``breakpoint-address-bits``. The host
data path is pinned by ``dfcntrl-wideodd``, ``internal-refusal-pci-status-clear`` (the refused bit
7), ``reserved-host-count-byte``,
``host-address-loads-scsi-address``, ``host-dma-memory-to-fifo``,
``host-dma-four-byte-offset``, ``dspcistatus-selector``,
``dspcistatus-resets``, ``pci-error-status-survives-chip-reset``,
``internal-scb-pointer/reset`` and ``internal-scb-alias/host``. Selection is
pinned by ``wide/registers``, ``wide/own-id``, ``wide/target-routing``,
``selection-timer-intervals``, ``selection-timer-late-enable`` and
``unmasked-selection-timeout``.
``tests/qtest/sgi-o2-test.c`` covers the O2 view of the controllers:
``o2/mace-pci-functional/unused-aic-config`` (configuration registers and
BARs), ``o2/aic-pci-diagnostic``, ``o2/storage-pio-aic-hcntrl`` and the
``o2/default-aic-*`` DMA cases against 64 MiB, 128 MiB and 1 GiB of RAM.
