.. _sgi-ics1890:

=============================
ICS1890: Ethernet transceiver
=============================

Used in :ref:`sgi-ip30`, on the Octane and Octane2 system boards, and
:ref:`sgi-ip32`, where the ``o2`` machine fits it although published O2s
report a DP83840 (:ref:`sgi-ip32-published`).

.. seealso::

   Platform pages: :ref:`sgi-ip30`, :ref:`sgi-ip32`.

The ICS1890 is a 10/100 Mb/s Ethernet transceiver. On the Octane it sits
behind the :term:`IOC3`'s MII management interface. QEMU models revision 3 as
``hw/net/ics1890.c``. The ``octane`` and ``octane2`` machines select it
on the onboard IOC3 with ``phy-ics1890=on`` at MII address 1; other IOC3
boards keep their own PHY (:doc:`ioc3`). The ``o2`` machine attaches one
to the MACE Ethernet MAC at MII address 8 (:doc:`mace-ethernet`). Its
register test profile attaches one only with ``phy-ics1890=on``.

Facts are rated as described in :ref:`sgi-ratings`.

.. _sgi-ics1890-sources:

Sources
=======

- The ICS1890 datasheet, revision G, :src:`ics1890-rev-g`. The register
  table's page column refers to it.
- Three published Octane boot logs, :src:`lore-seufer-octane-2005`,
  :src:`lore-walker-octane-2005` and :src:`lore-kinard-octane-2019`. Each
  reports one PHY at address 1 with vendor ``0x15f42``, model 2,
  revision 3. The 2019 log comes from a HEART F, :term:`Bridge` D board.
- Linux ``drivers/net/ethernet/sgi/ioc3-eth.c`` and OpenBSD
  ``sys/dev/mii/icsphy.c`` and ``icsphyreg.h``, as software expectations.
- The IOC3 MII registers read on the reference Octane2
  (:ref:`sgi-ics1890-measurements`).

Identity and address
====================

The datasheet's identity tables give words ``0x0015`` and ``0xf423``; model
2 is the ICS1890 and revision 3 is the J release or later
:src:`ics1890-rev-g p. 23-24`, *established*. The three boot logs decode to
the same words at address 1, *observed* on Octanes from 2005 and 2019
(:src:`lore-seufer-octane-2005 PHY probe`,
:src:`lore-kinard-octane-2019 attached dmesg`). On the reference Octane2,
board ``030-1467-001`` revision B, the :term:`PROM`'s last MII transaction read
register 1 at address 1 and got ``0x7809``
(:ref:`sgi-ics1890-measurements`), so a PHY answers at address 1 on that
board, *established*. That word is the ICS1890's status reset value with
the link down, but any 10/100 PHY that can negotiate and has no link
reads the same, so that the part is an ICS1890 is still *inferred* from
the 2019 capture; its identity registers were not read.

The chip answers only its strapped five-bit address and implements registers
0-6 and 16-19 :src:`ics1890-rev-g p. 17`. The model answers address 1. At
any other address the IOC3 returns ``0xffff`` and drops writes.

Command override
================

Setting extended-control bit 15 arms override. The next write to any
register at this address may then change that register's override bits, and
consumes the override; reads do not :src:`ics1890-rev-g p. 29`,
*established*. Address bits and read-only fields stay protected. A write to
extended control that arrives while override is armed and itself sets bit 15
consumes the old override without arming a new one, an *approximation*: the
datasheet does not order the two effects.

Reset, power-down and loopback
==============================

BMCR bit 15 is a self-clearing software reset that restores defaults within
500 ms :src:`ics1890-rev-g p. 19`, *established*. The model completes it at
once, cancels any pending negotiation and discards latched events and
command override.

Bit 14 loops MII transmit back to MII receive and isolates the external path
:src:`ics1890-rev-g p. 19`. The model delivers looped frames through the
IOC3's own receive path at either speed, whatever the backend's link state,
and never sends them to the network backend. Isolate (bit 10) and power-down
(bit 11) both stop external and looped traffic while management access keeps
working, *established* :src:`ics1890-rev-g p. 19-20`.

Entering power-down clears the latching status fields: BMSR ``0x0016``,
expansion ``0x0012``, Quick Poll ``0x3fe7`` and 10BASE-T polarity ``0x4000``
:src:`ics1890-rev-g p. 3, 9, 21-32`, *established*. While powered down no
negotiation completes and the link stays down. On release the datasheet says
only that error conditions reset :src:`ics1890-rev-g p. 20`. The model
clears fault and jabber history in BMSR (``0x0012``), parallel-detection
fault in expansion (``0x0010``) and receive-error, jabber and remote-fault
history in Quick Poll (``0x07e6``), an *approximation*. An enabled
negotiation then starts afresh.

Link and negotiation
====================

Negotiation picks the highest common mode in the order 100BASE-TX full
duplex, 100BASE-TX half duplex, 10BASE-T full duplex, 10BASE-T half duplex
:src:`ics1890-rev-g p. 8-9, 27`, *established*. Quick Poll reports
completion in bit 4, duplex in bit 14 and speed in bit 15. Its progress
field, bits 13-11, keeps the furthest progress until read; a completed
negotiation shows 7 :src:`ics1890-rev-g p. 30-31`.

A packet backend has no link partner, so the model supplies one, an
*approximation*: it advertises ``0x01e1`` with no faults and no next page,
and negotiation completes 100 ms of virtual time after reset release or an
enabled restart, provided the backend link is up and the two advertisements
share a mode. The datasheet calls usual negotiation shorter than half a
second; it does not give this delay. Status reads never start, finish or
delay negotiation. Backend link-down clears the live link; recovery starts
a new negotiation. With negotiation disabled, the configured speed and
duplex are reported without partner abilities.

Driver disagreements
====================

OpenBSD's shared ICS189x header calls register ``0x12`` bit 4 a loopback
control. On the ICS1890 it is reserved and must be written one
:src:`ics1890-rev-g p. 32`; the model does not loop on it. OpenBSD also
names register ``0x13`` bits 1 and 2; the ICS1890 reserves them and requires
zero :src:`ics1890-rev-g p. 34`. The datasheet's register 6 table marks bits
15-5 override-writable while its prose calls them zero; the model follows
the table. The datasheet's own cross-references put Quick Poll speed at bit
14 :src:`ics1890-rev-g p. 20`, completion at bit 5
:src:`ics1890-rev-g p. 31` and transmitted remote fault at advertisement bit
15 :src:`ics1890-rev-g p. 35`; the register tables, the public drivers and
the model use bits 15, 4 and 13.

.. _sgi-ics1890-measurements:

Measurements
============

The reference Octane2 (:ref:`sgi-measured-octane2`) was read through the
IOC3's MII registers in the PROM :term:`Command Monitor` after the firmware had
initialised the machine. No PHY register was written or read directly.

.. code-block:: text

   >> dump -w -x 0xffffffffbf600148#2
   0xffffffffbf600148:         21       7809

.. list-table::
   :header-rows: 1

   * - Address
     - Width
     - Value
     - Register
     - Part revision
     - When
   * - ``0x1f600148``, IOC3 ``0x148``
     - 32
     - ``0x21``
     - IOC3 MII control
     - not read
     - PROM monitor, after initialisation
   * - ``0x1f60014c``, IOC3 ``0x14c``
     - 32
     - ``0x7809``
     - IOC3 MII read data
     - not read
     - PROM monitor, after initialisation

MII control ``0x21`` decodes under Linux ``ioc3.h`` as register 1 in bits
4:0, PHY address 1 in bits 9:5 and busy clear. The read data is that
register's value: BMSR ``0x7809``, 100BASE-TX and 10BASE-T at both
duplexes, negotiation ability and extended capability, with link status,
negotiation complete and every fault bit clear. Link status is latch-low,
so a clear bit shows the PHY reported link down at the PROM's last read of
the register, which is *inferred* to be this transaction. The kernel booted
afterwards warned ``ef0: link fail - check ethernet cable``. This
establishes the PHY address. It does not establish the part, its revision, its straps or any other
register.

.. _sgi-ics1890-limits:

Model limits
============

- The two mode straps, node mode and software-configuration priority, are
  model choices; the board's real strapping is unmeasured. They give
  extended control 2 the value ``0x4001``. The address strap, 1, matches
  the reference Octane2.
- Reserved bits whose read value the datasheet leaves open read zero,
  except extended-control bit 4, which reads one in every state and cannot
  be written. The stock IP30 diagnostic expects that one. Together with
  address 1 and bit 3 this gives extended control ``0x0058`` after reset.
- 10BASE-T operations bit 4 reads one, its table default; its read value
  is otherwise unspecified.
- Register ``0x13`` bit 10 keeps its derived status on writes.
- Electrical tests, polarity, squelch, symbol and jabber generation have
  no packet-level equivalent. Selecting one logs ``LOG_UNIMP``; reserved
  write-zero bits written as one log ``LOG_GUEST_ERROR``. Reads of
  unimplemented registers log ``LOG_UNIMP``.
- Migration works only between identical builds.

Tests
=====

``tests/qtest/ics1890-test.c`` covers the identity scan at all 32
addresses, the access masks with and without override, both reset paths,
loopback at both speeds, isolate and power-down, the latch masks,
negotiation timing and migration. ``tests/qtest/sgi-ioc3-eth-test.c``
repeats the IOC3 checks with this PHY fitted.
