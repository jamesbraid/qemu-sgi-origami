## PCI configuration Status

The first implementation uses PCI Status `0x02b0` after cold reset as an
evidence-bounded compatibility value. It sets these read-only fields:

| Mask | Meaning |
|---:|---|
| `0x0200` | DEVSEL bits 10:9 are `01b`, which means medium timing. |
| `0x0080` | The target accepts fast back-to-back transactions to different agents. |
| `0x0020` | The function is 66 MHz capable. This describes device capability, not the 33 MHz IO-8 bus speed. |
| `0x0010` | The function implements a New Capabilities list, and configuration offset `0x34` points to its first entry. |

Library Mail aggregate `all`, Message-ID
`20050105190836.56872c22@gibson`, lines 216-226 and 250-260, contains raw
configuration bytes for two ISP12160 Revision ID `0x06` functions. Both expose
Status `0x02b0`, capability pointer `0x44`, and a Power Management version 1
capability at that address. Message-ID `4415F863.9040203@simg.de`, lines
388-403, independently decodes the same fixed Status properties and Power
Management capability on another Revision ID `0x06` function. Both are
post-initialization captures on other systems. They establish the same-silicon
configuration but do not directly observe an Origin 300 cold reset.

Status bit `0x0010` requires a real capability list. PCI 2.2 printed pages 197
and 213 require offset `0x34` to point to a dword-aligned capability containing
an ID, a next pointer, and capability-specific registers. The initial model
therefore exposes the captured Power Management version 1 capability at
`0x44`. QLogic's data sheet independently states Power Management revision 1.0
support and names D0, D3hot, and D3cold. PCI 2.1 did not assign bit 4 to User
Definable Features. Its printed page 192 reserves bits 0-4 and assigns that old
facility to bit 6, mask `0x0040`.

The exact physical Origin 300 reset word and capability bytes remain unknown.
A raw configuration-space capture after IO-8 PCI reset would replace this
compatibility selection. The register check must require the complete
`0x02b0` word and pointer `0x44` at offset `0x34`. The capability at `0x44`
must have ID `0x01`, Power Management version 1, and a zero next pointer.
This requires one bounded list entry without assigning values to the remaining
unobserved capability bytes.

## PCI configuration Command, Latency Timer and power management

The Origin 300 IO-8 board test `io8bt` writes three configuration registers on
this function and requires each to read back, reporting any mismatch as "Data
miscompare on SCSI while reading/writing PCI configuration registers" with the
register's dword index and its own `sec0_0.c line:262`. The values it writes are
observed directly, by tracing the configuration cycles of a whole diagnostic
run on the two-processor `origin300` machine (run `prom-20260923T155258-da743f`),
rather than inferred from what it expects back.

**Command, at offset `0x04`.** The test writes `0x156` and requires the whole
word: SERR enable (`0x100`), parity-error response (`0x040`), memory write and
invalidate (`0x010`), bus master (`0x004`) and memory space (`0x002`). The model
answered `0x00000106` at configuration address `0x920000000f021004` (run
`prom-20260923T153446-5d0349`). PCI lets a function hardwire any Command bit it
does not implement to zero, so reading all five back is what says this part
implements all five.

Two of those five are more than a guest normally sets, and the QLogic data sheet
corroborates both. Memory write and invalidate is one of the PCI cache commands
its PCI-interface list says the part supports. Parity-error response follows
from the compliance claim on its first page: PCI Local Bus Specification
revision 2.1, which requires a bus master driving PERR# to implement the bit
that enables it. The remaining Command bits — I/O space, special cycles, VGA
palette snoop, wait-cycle control and fast back-to-back — stay unobserved, and
the model leaves them read-only. *(all five writable: inferred from the
diagnostic's expectation, with memory write and invalidate and parity-error
response corroborated by the QLogic data sheet; the other bits unknown)*

**Cache line size and Latency Timer, at offset `0x0c`.** The test writes
`0xf8ff` and requires it back; the model answered `0x000000ff` (run
`prom-20260923T154343-a819ac`). The low byte is cache line size, which the PCI
core already lets a guest write. The byte above it is the Latency Timer, and the
write is what says this part implements it.

How wide that timer is stays unknown. The test writes zeros into its low three
bits, so it cannot tell a part that implements all eight from one that hardwires
the low three, and PCI lets a master implement only the upper bits. The model
makes the whole byte writable, matching what QEMU does for every other device
that implements the register, and the register-contract test asserts only the
value the test writes. A raw configuration dump after an all-ones write to that
byte would settle the width. *(the Latency Timer implemented: inferred from the
diagnostic's expectation; its width unknown)*

**Power-management control, at offset `0x48`.** This is the control word of the
capability at `0x44`. The test zeroes it, writes `0x100` — the event enable, with
the power state left at D0 — and requires `0x00000100` back. The model answered
`0x00000000` (run `prom-20260923T155057-732ccb`), because QEMU makes a whole PCI
capability read-only when it adds one. So this part holds that bit.

Nothing here establishes the rest of the word: the test never writes the power
state or the data-select field, so the model leaves both read-only. There is a
loose end worth naming rather than papering over. PCI power management makes the
event enable read-only on a function whose capability field reports no event
support, and this model reports none — the capability bytes past the version
number are the placeholders this datasheet already calls unobserved. The QLogic
data sheet claims only "the minimum power management capabilities specified in
revision 1.0" and lists the supported power states as D0, D3 hot and D3 cold,
which says nothing about event support either way. So either the shipped part
advertises it and this model's capability field is wrong, or the part holds the
enable without advertising it. The two mailing-list configuration captures the
PCI configuration Status section cites carry those bytes for same-revision
functions and would settle it; no read for this datasheet has decoded them.
*(the event enable holds a write: inferred from the diagnostic's expectation;
event support in the capability field unknown)*

All three register contracts rest on the board's own field diagnostic for where
the writable bits are, with the vendor data sheet corroborating two of the
Command bits. None of it transfers to the sibling ISP1040, a different chip on a
different board.

## PCI and host registers

The host accesses the following registers as 16-bit quantities. Offsets are
bytes relative to the controller register aperture, not PCI configuration
space. They are independently corroborated by Linux and NetBSD. The first
implementation boundary selects BAR size, byte order, access width and PCI
revision as compatibility behavior. Subsystem identity remains open.

| Offset | Register | Established consumer behavior |
|---|---|---|
| `0x06` | Bus configuration 1 | Selects internal register banks. Full writable mask and reset value remain open. |
| `0x08` | Interface control | Bit 0 requests soft reset. Bits 1 and 2 are the consumer's global and RISC interrupt enables. |
| `0x0a` | Interface status | Bits 1 and 2 identify PCI and RISC interrupt status. Complete assertion and clearing rules remain open. |
| `0x0c` | Semaphore | Reset initialization clears it. Ownership and collision rules remain open; see **The semaphore's busy bit is unsettled**. |
| `0x0e` | Serial EEPROM interface | Bits 0, 1, 2 and 3 carry clock, selection, output and input respectively. Timing and transaction details remain open. |
| `0x70` through `0x7e`, stride 2 | Eight mailboxes | Eight distinct 16-bit registers that carry command inputs and later results. |
| `0xc0` | Host command/control | Consumes command encodings, not independently OR-able command bits. |

NetBSD explicitly selects the 1080-family banked accessors for ISP12160.
Configuration-register values `0x0100`, `0x0200` and `0x0300` select SCSI
processor 0, SCSI processor 1 and DMA. These values identify bank selections,
not the full configuration value or writable mask. The accessors assume the
internal processor is paused during protected accesses.

The driver's DMA block adjustment of `0x60` plus the common register offset
`0x20` gives hardware offset `0x80`. Software block tags are not addresses.
Linux labels its direct command-DMA and data-DMA structure groups as
ISP1040-only. Those groups must not be copied into the ISP12160 address map.
The complete banked register map remains to be reviewed.

**The semaphore's busy bit is unsettled.** The Origin 300 IO-8 board test's SCSI
section, selected with `-S 0x1f`, writes the semaphore while it is already set and
requires bits 0 and 1 back, `0x3`, reading bit 1 as "semaphore in use by someone"; the
model answers `0x1` and the test fails with "Testing bus semaphore register busy bit
(2^1). Tried to write semaphore when it was already set" and its own `sec3_0.c
line:205` (run `prom-20260924T181150-35a3b5`). No published QLogic source states the
rule. The held QLogic documents are product data sheets that describe the host
interface without a register-level semaphore description: the ISP12160A data sheet
(`library/cache/io-chip/qlogic-isp12160a-datasheet-1999.pdf`, four pages), and the
ISP1000, ISP1020B/1040B (including its character-recognised text), ISP1040B,
ISP1040C, ISP1080, ISP10160A, ISP1240 and ISP1280 data sheets beside it, none of which contains
the word "semaphore"; a scoped Library search of the project documents and technical
publications found no QLogic technical manual. The model therefore keeps bit 1 as
plain storage and the section stays a known gap. A QLogic ISP technical manual with
the semaphore register's definition, or a register read on a real part, would settle
it. *(unknown)*

## Reset and readiness

Both drivers request soft reset through interface-control bit 0 and wait for
that bit to clear. Mailbox commands become usable only after reset readiness.
The shared initialization programs bus configuration, resets the internal
processor, clears the semaphore, releases the processor and waits for mailbox
0 to leave busy state `0x0004`.

The consumed host commands are reset `0x1000`, release `0x3000`, host-interrupt
set `0x5000`, host-interrupt clear `0x6000`, RISC-interrupt clear `0x7000` and
BIOS disable `0x9000`. The header also names pause `0x2000`. The full state
transition and visible status for pause still require review.

Linux also writes composite `0xb000`. The existing independent review found
that this comes from combining three command values. Its decode is unresolved.
It must not be implemented as three ordered effects merely because that is how
the expression was written. NetBSD supplies an independent sequence of
separate reset and release commands.

Physical cold-reset contents of RAM, banks, mailboxes and queue pointers are
not established by driver initialization writes. The first implementation
boundary selects a deterministic compatibility state. Reset delay, accesses
during reset and in-flight DMA cancellation still need a contract.

## Mailboxes and controller RAM

A host-interrupt command submits mailbox work. Completion needs output state,
interrupt assertion and acknowledgement. Returning a constant success value
without processing inputs cannot satisfy the register-test contract.

| Command | Required behavior | Unresolved details |
|---|---|---|
| `0x0006`, mailbox test | Return distinct submitted nonzero patterns in the tested mailboxes and complete the command. Linux checks 1–7, NetBSD checks 1–5. | Pending-command collision and output update timing. |
| `0x0004`, family-compatible write RAM word | Store mailbox 2 at the word address in mailbox 1. | Physical RAM bounds and bad-address response. |
| `0x0005`, family-compatible read RAM word | Return the word addressed by mailbox 1 in mailbox 2. | Physical RAM bounds and bad-address response. |
| `0x0009`, A64 RAM load | Copy mailbox 4 words from translated host DMA memory to the word address in mailbox 1. | RAM bounds, failed-DMA result and partial-copy behavior. |
| `0x0001`, flat load RAM | Copy mailbox 4 words from the four-mailbox host address to the word address in mailbox 1, the same block cycle the A64 load uses under a distinct opcode. Observed issued by the stock BASEIO PROM 6.210 SCSI diagnostic's DMA test, correcting this sheet's earlier exclusion of the opcode. | RAM bounds, failed-DMA result and partial-copy behavior. |
| `0x0003`, flat dump RAM | Copy the word range starting at mailbox 1 to the four-mailbox host address, the same block cycle in the other direction. Observed issued by the stock BASEIO PROM 6.210 SCSI diagnostic's DMA test alongside `0x0001`. | RAM bounds and failed-DMA result. |
| `0x0007`, verify checksum | Sum the stored image described in the reviewed firmware abstraction and fail a corrupt image. | Malformed length and out-of-range response. |
| `0x0002`, execute firmware | Complete without interpreting controller instructions; the modeled mailbox and queue interface remains live. | Invalid-start response, if the selected guest or diagnostics observe one. |
| `0x0052`, initialize A64 request queue | Preserve a separate request length, DMA address and index. | Index validation and nonzero returned indices. |
| `0x0053`, initialize A64 response queue | Preserve a separate response length, DMA address and index. | Index validation and nonzero returned indices. |

Reuse these initialization commands from the functional ISP1040 model. They
are part of the modeled firmware interface and do not imply controller-program
execution:

| Command | First implementation behavior |
|---|---|
| `0x0000`, no operation | Complete without changing controller state other than the mailbox result and interrupt. |
| `0x0008`, about firmware | Return version 10.4.0, matching the selected IRIX ISP12160 program, with attribute word zero. |
| `0x001f`, get firmware status | Report no commands currently executing and a 512-request limit, preserving the existing functional-model policy. |
| `0x0028`, get target parameters | Return asynchronous, narrow defaults for the selected channel and target. Keep the ISP12160 PPR output separate from the older part and zero by default. |
| `0x0030`–`0x0039`, configuration setters | Accept the individual initiator, timeout, retry, tag-age, clock, active-negation, asynchronous-setup, PCI-control, target-parameter and device-queue commands already named by the public family interface. Keep channel and target selectors distinct. A setter with no reviewed readback may be an acknowledged no-op; `0x0038` does not change the `0x0028` reply until its field mapping is reviewed. |
| `0x003a`, set reset-delay parameters | Accept and retain separate per-channel values for later bus-reset selection. |
| `0x0045`, set system parameter; `0x004a`, set firmware features; `0x005a`, set data-overrun recovery | Accept as compatibility commands. Retain values only where a reviewed getter or later operation consumes them. |

The selected image version is a returned interface value, not an image match:
accept any checksum-valid guest download with the reviewed shape. Do not compare
the RAM contents against the retained IRIX object. Configuration commands that
stock IRIX or diagnostics read back need a field-level contract before their
getters report success.

Completion code `0x4000` is distinct from invalid command `0x4001`, host
interface error `0x4002`, test failure `0x4003`, command error `0x4005` and
parameter error `0x4006`. Specific invalid inputs must be mapped to those
results from evidence, rather than assigning one generic error everywhere.

Request and response initialization must work in either order: the two reviewed
drivers use opposite orders. Each A64 command carries four 16-bit address
pieces. Linux's queue initialization at the cited revision, lines 1870–1924,
uses this mapping for both commands:

| Mailbox | Input |
|---|---|
| 1 | Queue length |
| 2 | DMA address bits 31:16 |
| 3 | DMA address bits 15:0 |
| 6 | DMA address bits 63:48 |
| 7 | DMA address bits 47:32 |
| 4 for request, 5 for response | Initial index, zero in the reviewed Linux sequence |

Thus Linux supplies `(mb6 << 48) | (mb7 << 32) | (mb2 << 16) | mb3`, with
each word widened before shifting. NetBSD `isp.c` lines 1255–1334 supplies the
same four word positions but exposes a source inconsistency: its request
initialization takes the low words from the request buffer and the high words
from the response buffer. That sequence could work when both buffers share
upper address bits. It does not establish that hardware substitutes the
response address into the request queue.

The command input masks agree. NetBSD `isp.c` lines 6710–6711 selects
mailboxes 0, 1, 2, 3, 4, 6 and 7 for request initialization (`0xdf`), and
0, 1, 2, 3, 5, 6 and 7 for response initialization (`0xef`). These match
Linux's masks. NetBSD's mailbox initializer, `ispreg.h` lines 483–490, zeroes
the entire command structure first. Its explicit assignments to request
mailbox 5 and response mailbox 4 therefore affect unused inputs. The submitted
request mailbox 4 and response mailbox 5 are already zero. Both consumers
support the same zero-index input path. Nonzero-index behavior remains open.

Tests must use different upper address words for the two queues, distinct words
within each address and nonzero upper bits to detect truncation, swapped words
and accidental cross-queue reuse. Independent queues do not imply that channel
configuration is shared.

The existing ISP1040 model is the firmware abstraction precedent. It retains
guest-downloaded words in controller RAM, verifies their checksum, accepts the
execute command, and implements the mailbox and queue behavior directly. It
does not interpret controller instructions or load a separate host-side
firmware blob. ISP12160 follows that boundary. Its register and RAM tests must
still reject discarded writes and unconditional checksum success.

## Reviewed RAM loading and execution boundary

The RAM and firmware review (citation: `docs/reviews/isp12160-ram-firmware-contract-review.md`)
compares Linux and NetBSD at the source revisions recorded here. Controller
addresses and transfer counts for commands `0x0004`, `0x0005` and `0x0009`
are measured in 16-bit words. Advancing a controller address by one selects
the next word. A DMA source advances by two bytes per word.
Commands `0x0004` and `0x0005` are shared SCSI-family compatibility behavior,
not directly observed ISP12160 consumption in these sources. NetBSD defines
them in its shared command table and continuation path, but the retained build
has no compiled-in ISP12160 program. The reviewed Linux ISP12160 loader
consumes command `0x0009`.

For command `0x0009`, mailbox 1 is the destination word address and mailbox 4
is the word count. The host DMA address is
`(mb6 << 48) | (mb7 << 32) | (mb2 << 16) | mb3`, with each word widened
before shifting. Completion requires the actual translated DMA read and RAM
copy. Linux's 1,000-word chunks are driver policy, not a hardware maximum.

The DMA payload is a little-endian word stream at the controller's PCI-facing
DMA interface. Linux copies its little-endian firmware words unchanged into
the staging buffer. Its word-at-a-time path instead converts each word to the
numeric mailbox value. Thus bytes `34 12 cd ab` supply RAM words `0x1234` and
`0xabcd`. Test this with unequal bytes in every word. Interpret the bytes
returned by the device DMA address space, after any upstream bridge swapping,
without an additional host-CPU-endianness conversion.

The 16-bit address field does not prove that all 65,536 words are physically
populated. The first implementation boundary explicitly adopts that allocation
as a compatibility policy and rejects transfers crossing its end without
wrapping. The physical RAM size and reset contents remain unknown. The DMA
failure result is unresolved; the compatibility policy rejects a failed read
without committing a prefix. Extended word commands and A64 dump are outside
this cleared subset. Flat load RAM `0x0001` and dump RAM `0x0003` follow the same
block-transfer boundary as the commands above: the stock BASEIO PROM 6.210
SCSI diagnostic prepares both against the ISP12160, which supersedes this
sheet's earlier reading of them as unobserved on this part. Their opcode values,
mailbox layout and directions are independently cleared; see the status note
at the top of this sheet.

Checksum command `0x0007` supplies a starting word address in mailbox 1. Follow
the existing ISP1040 abstraction: read the image length from zero-based word
index 3 relative to that start, which is the fourth image word; add that many
stored 16-bit words modulo 65,536; return the sum in mailboxes 1 and 2; and
complete only when the sum is zero. The selected IRIX
object carries a separate ISP12160 program of `0x361d` words and its image
header's fourth word is also `0x361d`, matching that family format. A test must
load a small checksum fixture constructed by the test, corrupt one word and
observe checksum failure.
Malformed lengths and ranges must fail without wrapping; the exact completion
code remains open.

Execute command `0x0002` also supplies a starting word address in mailbox 1.
It completes without interpreting controller instructions. Mailbox commands and
queues are the modeled firmware interface and are available without a QLogic
RISC execution engine. QEMU does not locate or load an ISP12160 program itself;
stock IRIX downloads its own image through the modeled RAM command. The execute
acknowledgement does not qualify the rest of the device: RAM, checksum, queue,
SCSI transfer and recovery tests remain behavioral requirements.

RAM tests must use distinct words, a nonzero destination, translated DMA,
and sentinel words outside the loaded span. They must detect byte-versus-word
addressing mistakes, discarded writes, address truncation and wrapping. These
tests qualify RAM loading only, not checksum verification or execution.

## Reviewed mailbox interrupt sequence

Root checked Linux `qla1280.c` at the cited revision, lines 1050–1107,
2410–2539 and 3330–3484. The independent mailbox interrupt review (citation: `docs/reviews/isp12160-mailbox-interrupt-review.md`)
compares the NetBSD path and clears the bounded behavior described here. It
does not clear a complete interrupt state machine.

The host writes command-selected mailboxes, then writes host-command `0x5000`.
The interrupt routine reads interface status, saves mailbox 5, and checks
semaphore bit 0. A mailbox event with that bit set supplies output registers.
Linux copies those values before writing semaphore zero and host-command
`0x7000`. Asynchronous events and ordinary command completion are handled
separately. A routine entered without the semaphore bit also writes `0x7000`
and proceeds to the response-ring path.

Masking is distinct from clearing pending state. Linux disables interrupts by
writing interface control zero, then reads the pending RISC status and processes
the event. It later enables delivery with control bits 1 and 2 set (`0x0006`).
A model that clears pending status or mailbox data on interrupt disable would
break this consumed sequence. The source toggles both enable bits together,
so it does not establish the behavior of either bit enabled alone.

NetBSD acknowledges in the opposite order: host-command `0x7000`, then
semaphore zero. Both consumer sequences must complete the mailbox-only event.
Reads of status, semaphore and results do not acknowledge it. The pending event
must remain available while masked and become deliverable on restoring
`0x0006`. Neither source establishes partial-acknowledgement state, composition
with other interrupt causes, or physical ordering and timing guarantees. The
submission routine also notes that it does not check mailbox availability.
Its host timeout is twenty seconds, which is not a controller latency value.
Second-command collision behavior and exact completion timing remain open.

Tests for the completed contract must submit nonzero mailbox-test patterns,
observe event status and result data, disable delivery while retaining pending
state, and exercise the documented acknowledgement. Constant-success handling
or clearing an event by masking it must fail. Physical PCI interrupt delivery
through XBridge and Bedrock remains a separate machine integration check.

## SCSI channels and EEPROM

Both channels require independent initiator, target, timing and queue settings.
ISP12160's target configuration differs from ISP1040 in synchronous offset and
PPR fields. The two EEPROM bus records start at bytes 24 and 136 in the NetBSD
consumer layout, with six bytes per target record. The actual Origin 300 EEPROM
contents, checksum, serial protocol and reset defaults remain open.

The normal A64 queue layout and channel selector are defined in the reviewed
ring contract. The selected guest's abort-device and bus-reset request forms are
also reviewed. Remaining completion-error triggers, recovery races, ordering and
timing require further evidence; they do not block the bounded first model.
All PCI DMA must use the device DMA address space so XBridge translation applies.

## SCSI request and completion rings

The queue review (citation: `docs/reviews/isp12160-queue-contract-review.md`) clears this
bounded normal-I/O contract.
Linux `qla1280.h` lines 560–686 and `qla1280.c` lines 2736–2962 at the
cited revision define the A64 path described here. These are firmware-provided
interfaces. Their layout does not establish that an execution engine exists.

Each ring slot occupies 64 bytes. Multibyte numeric fields are little-endian
at the controller DMA interface. CDB and sense data remain byte arrays.
The A64 command uses type `0x09` and the following byte offsets:

| Offset | Width | Meaning |
|---|---|---|
| `0x00` | 1 | Entry type, `0x09`. |
| `0x01` | 1 | Total slots occupied by this command, including continuations. |
| `0x02` | 1 | Host-defined byte. Linux supplies its request index truncated to a byte. |
| `0x03` | 1 | Entry status, zero in submitted Linux requests. |
| `0x04` | 4 | Opaque host handle returned with completion. |
| `0x08` | 1 | LUN. |
| `0x09` | 1 | Target with bit 7 selecting channel 1 instead of channel 0. |
| `0x0a` | 2 | CDB byte count. |
| `0x0c` | 2 | Control flags. |
| `0x0e` | 2 | Reserved in this format. |
| `0x10` | 2 | Command timeout. Linux supplies seconds. |
| `0x12` | 2 | Total data segment count. |
| `0x14` | 12 | CDB storage. |
| `0x20` | 8 | Unused and zero in the reviewed Linux request. Further semantics remain unresolved. |
| `0x28`, `0x34` | 12 each | Two DMA descriptors. |

Each descriptor contains address bits 31:0, address bits 63:32, then a byte
length, each as a little-endian 32-bit quantity. Additional descriptors use
continuation type `0x0a`. Its first four bytes have the common entry header,
and five descriptors begin at byte `0x04`, with stride 12. Linux sets each
continuation's entry count to one. The first command's count includes all
continuations. A chain may wrap from the last request slot to slot zero.
Reserved fields being zero in a driver submission does not define hardware
reset values or acceptance of nonzero inputs.

NetBSD's shared A64 builder uses a different interpretation: a 16-byte CDB
and a total byte count at `0x24`. Its retained PCI attachment disables that
A64 path because of a driver problem. This corroborates descriptor placement,
not the differing CDB/count fields on ISP12160. The selected normal-I/O
contract accepts Linux's consumed 12-byte CDB form with bytes `0x20`–`0x27`
zero. It does not establish that longer CDBs are impossible or that those bytes
have no meaning on hardware.

Linux `qla1280.c` lines 443–462 maps control bit 5 to data from the target
into host memory and bit 6 to host memory sent to the target. It sets bit 3
for simple tagged requests. It also defines both direction bits together for
bidirectional requests, but that alone does not specify their transfer sequence.
The exact handling of malformed CDB lengths, inconsistent descriptor counts,
address overflow, unsupported control combinations and failed DMA remains open.

During queue operation, a host write to mailbox 4 publishes the next request
producer index after the entries have been written. Reading mailbox 4 returns
the controller's request consumer index. Reading mailbox 5 returns the response
producer index, while the host writes mailbox 5 to release consumed responses.
These directional cursor roles cannot be modeled as one shared read/write value
per mailbox. Their multiplexing with mailbox commands requires the controller
state machine. Producer/consumer indices wrap at their separately initialized
queue lengths. Linux's spare-slot reservation is driver policy, not a proven
hardware capacity limit.

A normal response uses entry type `0x03`. Linux `qla1280.h` lines 560–591
and `qla1280.c` lines 3470–3649 define these fields:

| Offset | Width | Meaning |
|---|---|---|
| `0x00`–`0x03` | 1 each | Type, count, host-defined byte, entry status. |
| `0x04` | 4 | Submitted handle. |
| `0x08` | 2 | SCSI status. |
| `0x0a` | 2 | Controller completion status. |
| `0x0c` | 2 | Command state flags. |
| `0x0e` | 2 | Status flags. |
| `0x10` | 2 | Time field. |
| `0x12` | 2 | Sense byte count. |
| `0x14` | 4 | Residual byte count. |
| `0x18` | 8 | Reserved in this format. |
| `0x20` | 32 | Sense data. |

Completion must follow the actual SCSI operation and required data transfers.
The response bytes must be visible before publishing the producer index and
notifying the host. The controller must preserve responses that the host has
not released. Full-ring behavior, remaining error triggers, time units,
all state-flag combinations, fast posting and reset/abort interactions remain open.
A driver accepting a zero status does not permit reporting success for work
that never executed.

Tests must send distinct handles to the same target number on both channels,
read different disk contents, and verify write persistence. Exercise more than
two segments, a continuation across ring wrap, independent queue lengths and
DMA addresses with different nonzero upper words. Protect bytes outside each
descriptor with sentinels. Confirm request consumption and response publication
through their separate cursor roles. Invalid and failed transfers must not be
reported as successful payload operations. These checks do not clear the
remaining mailbox or diagnostic requirements.

## Completion status, residuals and sense

The completion review (citation: `docs/reviews/isp12160-completion-contract-review.md`)
clears the bounded behavior and model choice described here.
Linux `qla1280.h` lines 926–960 and `qla1280.c` lines 1286–1390 and
3600–3679 at the cited revision distinguish controller completion from target
SCSI status. Controller completion zero means the transport completed. It does
not turn a target's check condition, busy or queue-full status into SCSI success.
Return the actual target status in the response's low SCSI-status byte.

| Controller completion | Consumer interpretation | Contract limit |
|---|---|---|
| `0x0000` | Transport completed. | Required command and payload work must have completed. Preserve the separate target status. |
| `0x0001` | Command incomplete. | State flags describe the reached phases. Linux distinguishes failure to obtain the bus from failure to select a target. |
| `0x0002` | DMA direction error in the Linux header. | This name does not establish the result of every failed PCI mapping or memory transaction. |
| `0x0004`, `0x0005`, `0x0006` | Reset, aborted command and timeout respectively. | Encodings alone do not establish cancellation, timer or completion ordering. |
| `0x0007` | Data overrun. | Overrun trigger and residual representation remain unresolved. |
| `0x0015` | Data underrun. | Residual is the number of requested bytes not transferred. |
| `0x001c` | Internal controller queue full. | Distinct from target queue-full status. Its hardware trigger remains unresolved. |
| `0x001e` | Automatic request-sense failure. | Do not claim usable automatic sense data for this result. |

The phase flags occupy bits 8 through 14: bus acquired, target selected, CDB
sent, data transferred, status received, sense received, and transfer complete.
For incomplete commands, Linux checks bus and target flags before the later
phases. A model must not set a phase flag for work it skipped. The reviewed
consumer does not establish every valid flag combination or a unique missing-
target response.

For a realized SCSI bus with no attached device at the selected target, the
functional model selects completion `0x0001`, bus-acquired bit 8 set, and
target-selected bit 9 clear. Later phase bits stay clear because no command
reached a target. Linux interprets this as a bad target and NetBSD as selection
timeout. This reviewed compatibility choice defines the result and reached
phases. It does not establish hardware latency or the residual field for this
case. No payload DMA or other target's operation may substitute for the absent
device.

The status-flag word for this case is established as a consumer expectation, not
as silicon behavior. Stock IRIX 6.5.30 validates it. With the word clear, the
kernel declares a hard error for every absent target on the bus during its scan;
with selection-timeout bit `0x0040` set, it accepts the empty slot silently.
Both behaviors were observed on the emulated Origin 200 with this adapter as a
plug-in at PCI device 4: the word clear in
the 2026-09-07 boot (citation: `docs/boot-logs/irix.boot.2026-09-07T05:41:01-07:00`), the bit
set in the 2026-09-06 boot (citation: `docs/boot-logs/irix.boot.2026-09-06T09:25:29-07:00`).
The two built-in single-channel adapters keep the bit and logged nothing in
either boot, which separates the kernel's reaction from ordinary scan noise. The
IRIX exercise notebook (citation: `docs/notebooks/isp12160-irix-exercise.md`) records the run
conditions, the message shape and the counts. The model therefore sets bit
`0x0040` for this case as a compatibility selection matching the selected IRIX
guest. This is one consumer's requirement observed on our own model
and not a hardware measurement: what real silicon reports in this word, how long
it takes to report it and what it leaves in the residual field all remain open.

For underrun, publish the actual residual at response byte `0x14` and preserve
bytes outside the transferred portion. Linux compares requested length minus
residual against the command's underflow threshold. That threshold is host
policy. The adapter must not pad missing bytes or report a full transfer merely
to satisfy it. Residuals larger than the requested transfer and malformed
scatter/gather capacity remain separate unresolved error cases.

A check-condition response needs the actual sense bytes and their length when
automatic sense succeeds. Set state bit 12 when target status was received
and bit 13 when sense was received. NetBSD's SCSI path uses these flags to
accept status and sense respectively. Fibre Channel validity bits in the
SCSI-status word do not replace these SCSI phase flags. The status entry has
32 bytes of inline sense storage at `0x20`. Linux's copy limit can exceed that
inline capacity, so its host copy
code does not authorize a controller to write beyond the entry. Longer sense
handling and truncation semantics remain open. Busy and target queue-full
responses retain the target status without fabricating successful payloads.
For controller completion `0x001c`, NetBSD synthesizes target queue-full when
the supplied target status is good. This is a consumer fallback for the
internal-full indication, not evidence that target busy or queue full should
be converted to controller completion `0x001c`.

Linux also names completion values `0x80`–`0x82` as driver-defined. Those
constants are not evidence for controller-produced completion values. Likewise,
queue-entry status flags for bad header, bad payload and full conditions do not
by themselves specify which malformed request produces which response.

Tests must distinguish transport success with target check condition from a
successful SCSI command. Check the returned handle, actual sense payload and
length, short-transfer residual and untouched destination sentinels. Repeat on
both channels with different pending handles. A failed transfer must not update
the other channel's request or disk. Test the selected missing-target result
and phase flags without claiming to qualify selection timing. DMA-fault, reset
and abort tests require their remaining trigger and ordering contracts first.

## Command abort and SCSI reset

The recovery review (citation: `docs/reviews/isp12160-recovery-contract-review.md`)
clears the Linux argument format and bounded client requirements. The retained
IRIX 6.5.30 IP35 object additionally establishes the selected guest's
abort-device and bus-reset submissions. It does not clear every recovery race
or error result. Linux `qla1280.h` lines 268–300 and `qla1280.c` lines
2540–2671 at the cited revision define these consumed mailbox requests:

| Command | Inputs | Selected scope |
|---|---|---|
| `0x0015`, abort command | Mailbox 1 contains channel in bit 15, target in bits 14:8 and LUN in bits 7:0. Mailboxes 2 and 3 contain handle bits 31:16 and 15:0. | One outstanding command identified by that handle and address. |
| `0x0017`, target reset | Mailbox 1 contains channel and target in its upper byte. Linux supplies zero in its lower byte and one in mailbox 2. | The selected target on one channel, across its LUNs. |
| `0x0018`, bus reset | Mailbox 1 carries the configured reset-delay value. Mailbox 2 selects the channel directly. | The selected SCSI channel. |

Mailbox masks are `0x0f` for command abort and `0x07` for target and bus
reset. The abort handle is `(mb2 << 16) | mb3`, with the high word widened
before shifting. This differs from the four-mailbox A64 DMA address layout.
The selected IRIX object contains call references to both recovery helpers and
constructs these requests:

| Command | Inputs | Selected scope |
|---|---|---|
| `0x0016`, abort device | Mailbox 1 contains channel in bit 15, target in bits 14:8 and LUN in bits 7:0. Mailboxes 2 and 3 are zero. | Outstanding requests for one LUN on one target and channel. This scope is the bounded functional interpretation of the explicit selector; the object does not expose a separate request handle. |
| `0x0018`, bus reset | Mailbox 1 contains a byte read from the selected channel's state. Mailbox 2 contains the channel number. | The selected SCSI channel. The object alone does not name the mailbox-1 value or assign it time units. |

The IRIX bus-reset shape independently matches Linux's mailbox placement. The
abort-device command is distinct from command-abort `0x0015`: it carries no
handle and applies to the packed channel, target and LUN selector. It is also
distinct from target-reset `0x0017`, whose reviewed Linux selector omits the
LUN. Do not alias these commands.

NetBSD is not independent confirmation of the abort-handle layout. Its retained
path puts the handle in mailbox 2 without a second word, whereas Linux puts
the low word in mailbox 3. NetBSD also assigns the channel/target selector
before an initializer clears the mailbox structure. That assignment does not
survive into its abort and target-reset submissions. Its bus-reset delay and
channel are also cleared before submission. These source differences
must not be converted into an automatic choice between live handles or a
hardware alias. The table records the Linux ISP12160 consumer. The firmware
interface used by the selected IRIX path is the separate table in this section.

The Linux recovery path at lines 748–951 waits for the affected SCSI commands
separately from issuing the mailbox command. After target reset it waits for
commands on the selected channel and target. After bus reset it waits for
commands on the selected channel. Returning mailbox success while leaving the
affected requests permanently outstanding cannot satisfy that sequence.

A command may complete naturally while the host submits an abort. Linux
explicitly allows that race and waits for the command to finish rather than
using the abort mailbox result as the sole outcome. The controller must keep
mailbox acknowledgement and SCSI request retirement distinct. This consumer
does not establish that one always precedes the other. A request must be
retired once, with its own handle. A late backend callback must not complete
it again or transfer more data after its retirement.

Recovery must respect its selected scope. A command abort must not cancel an
unrelated handle. Target reset must not reset another target or the same target
number on the other channel. Bus reset must not cancel requests on the other
channel. These are functional-model isolation requirements from the explicit
selectors and the host's filtered waits. Handling of a mismatched handle and
address, an unknown handle, partially completed transfers, and the exact
completion code in each race still require a contract.

On successful bus reset, Linux sleeps for the configured delay in seconds
and then submits a synchronize-all marker for that channel. Target reset is
followed by a synchronize-target marker, even when the mailbox command failed.
These are observed host sequences, not proof of hardware reset-pulse duration
or mailbox completion latency. The value one in target-reset mailbox 2 does
not by itself define a timer. Marker encoding and ordering effects require
separate review. A marker is not evidence that the preceding reset succeeded.

Tests for the completed recovery contract must keep distinct commands pending
on both channels. Abort one IRIX-selected device, abort one Linux-selected
handle, reset one target, and reset one bus in separate cases, checking the
surviving requests and disk contents. Exercise a natural completion racing
with abort and reject duplicate retirement or late DMA. Reuse a retired handle
for a new command and ensure a delayed callback cannot affect that new request.
Observe mailbox acknowledgement and affected request completion separately.
Exact error replies, reset timing, marker ordering and partial-DMA recovery
remain unqualified until their remaining rules are reviewed.

## First implementation boundary

The first implementation is a functional ISP12160 model derived from the
existing ISP1040 device. These are explicit compatibility selections where the
sources do not establish physical reset values or internal execution:

- Add a distinct `qlogic-isp12160` QOM type with PCI identity `1077:1216`, SCSI
  class and interrupt pin A. Use PCI revision `0x06`, observed for the same part
  in a retained public hardware capture.
- Present the shared host register file through 256-byte I/O and memory BARs.
  Both BARs alias the same little-endian register state. Accept exactly 16-bit
  register accesses; invalid widths fail through the memory-region contract.
- Own two QEMU SCSI buses. The channel bit in each request and every mailbox
  selector chooses one bus. Target and LUN numbers are local to that channel.
- Allocate 65,536 16-bit controller-RAM words and clear them on device and soft
  reset. RAM commands reject a range whose widened start plus count exceeds the
  array; they do not wrap or commit a prefix after a failed DMA read.
- Complete supported mailbox commands synchronously when host-interrupt set is
  written. Preserve the result and pending interrupt until either reviewed
  acknowledgement order completes. A second submission while the semaphore is
  locked must not overwrite the first result; log it as a guest error and leave
  the pending command intact.
- Retain downloaded words and implement checksum as specified in this sheet.
  Acknowledge execute without an instruction interpreter. The remaining
  mailbox, queue, SCSI and recovery handlers provide the firmware behavior.
- Keep target settings, request and response queues, pending requests and
  recovery scope distinct per channel. Common PCI and host-interface state may
  remain shared where this sheet says it is common.
- Return zero and log `LOG_UNIMP` for an unimplemented readable register; ignore
  and log `LOG_UNIMP` for an unimplemented write. A mailbox opcode outside the
  implemented set returns invalid command. Do not silently report success.

These choices define an implementable starting state; they are not claims about
unobserved silicon. If stock IRIX or an SGI diagnostic observes a different
result, replace the compatibility choice with that recorded behavior and add a
qtest that distinguishes it.

The dedicated register suite must contain these behavior checks. Test names may
follow the surrounding qtest convention, but each outcome is required:

| Check | Stub or regression it must reject |
|---|---|
| PCI identity, revision, BAR size, 16-bit access and interrupt pin | An ISP1040 identity rename or an undecoded register window. |
| Three bank selections with unequal values at the same window offset | Aliased SCSI-processor and DMA banks. |
| Mailbox test with a different nonzero pattern in every mailbox | Constant success, zero results or aliased mailbox storage. |
| Word-write/read round trip at two nonadjacent addresses | Discarded writes, byte addressing or one backing word. |
| A64 RAM load through translated DMA with unequal bytes and sentinels | Host-endian copying, bypassed XBridge translation, truncation or overwrite. |
| Checksum success followed by one-word corruption and failure | Unconditional checksum success or checksum over the wrong span. |
| Execute acknowledgement followed by a stateful mailbox command | Treating execute as the complete device or gating modeled commands on an interpreter. |
| Firmware version/status and reset-delay settings on both channels | Image-content matching, a fatal unimplemented initialization command or aliased channel settings. |
| Masked mailbox completion followed by both reviewed acknowledgement orders | Clearing pending state on mask, read-to-clear behavior or stuck interrupt level. |
| Request and response initialization in both orders with unrelated 64-bit bases | Truncated addresses, shared queue state or order dependence. |
| A64 request with a continuation across ring wrap and real payload bytes | Header-only parsing, ignored continuations or success without DMA. |
| Same target and LUN on both channels with different disks | One SCSI bus, ignored channel selection or shared target state. |
| Short transfer and check condition with residual and sense sentinels | Zero-filled status stubs or sense overwrite. |
| Missing-target answer carrying the selection-timeout status flag | A cleared status-flag word, which makes stock IRIX log a hard error for every absent target on the bus. |
| IRIX abort-device and bus-reset selectors with unrelated work on the other channel | Cross-channel cancellation, handle-based decoding of `0x0016` or bus-wide reset. |
| Save and restore distinct queue, RAM, channel and pending state | A migration stream that aliases or drops ISP12160 state. |

Register the suite in the mips64 qtest build. `tools/check-qtest-registered`
must name and execute it; an unregistered green binary is not a pass.

## Reuse from ISP1040

ISP12160 belongs to the same controller family as ISP1040. The existing QEMU
controller supplies candidate SCSI request, disk backend and DMA machinery.
Reuse each operation only where this contract establishes matching behavior.
Keep ISP12160 bank selection, two-channel state, RAM commands and queue
initialization explicit. Reuse the established functional firmware abstraction:
retain the downloaded words for observable RAM and checksum operations, accept
execute without interpreting them, and implement the exposed mailbox and queue
interface in C. Shared mailbox offsets do not establish identical reset values
or every firmware command. Preserve ISP1040 tests alongside dedicated ISP12160
tests so extending the family cannot silently change the older part.

At fork `54ce1c3fabaec311812f94df4eb678c1b6122c35`, the existing controller
already has A64 request and continuation parsing, full-width DMA descriptors,
QEMU scatter/gather lists and SCSI request submission. Extend those mechanisms
where their behavior matches this contract. The current A64 request path
explicitly rejects a nonzero bus selector and owns one SCSI bus, so channel 1
requires real state and routing. Existing parsers still need validation against
the completed ISP12160 error contract before reuse is cleared.

The current migration callback recovers the adapter with `container_of()` from
its single `SCSIBus`. That cannot identify channel 1 after adding a second bus.
Use a small per-channel bus wrapper with adapter and channel back-pointers, or an
equivalent explicit mapping. Preserve channel, target and LUN for each in-flight
request so recovery and migration cannot act on the same numeric target on the
wrong bus. Bump the migration version for ISP12160 state without changing the
meaning of existing ISP1040 stream versions.

Keep the existing legacy command-line helper as the ISP1040 and channel-0 entry
point. If the Origin 300 board needs a channel-selecting helper, add it alongside
the existing interface instead of changing every Origin 200 caller. The machine
owner decides which channel receives the default boot disk; the controller
author exposes the two buses without wiring board policy into the device.

## Implementation ownership and acceptance

The controller author owns the ISP12160 behavior added to `hw/scsi/qlogic-isp.c`
and its dedicated qtests. Shared build declarations and existing ISP1040 tests
must be coordinated with the machine integration owner. The nested integration
checkout is not an editing destination. Preserve the existing ISP1040 behavior
and migration stream while defining ISP12160 state explicitly.

Register tests must reject discarded mailbox and RAM writes, aliased mailboxes,
aliased channel banks, unconditional checksum success, and queue commands that
do not retain their inputs. Execute is intentionally acknowledged without
instruction execution and is not, by itself, a qualification test. Tests must
also check reset readiness, interrupt masking and acknowledgement, independent
queue initialization in both orders, translated DMA and failed mappings once
their remaining error contracts are reviewed. Migration must preserve
meaningful in-flight state or reject an unsupported state explicitly under a
reviewed contract.

Disk tests must attach different contents at the same target number on both
channels, verify read payloads and write persistence, and test channel-specific
reset and abort. A completion code without transferred bytes is not a pass.

SGI `io8bt` includes PCI/reset checks, a controller section and concurrent board
stress. Its retained guide does not enumerate every controller subtest. Online
disk and CD-ROM tests add media checks. Internal RAM, processor-interface and
unused-channel coverage remain required by the full diagnostic goal. If a
diagnostic observes an internal processor result, model that documented result
at the firmware interface; it does not require a QLogic instruction interpreter.
Register qtests and a successful disk operation do not establish those results.
